# 《Into the Radius 2》加密文本破解报告

> # ⚠️ 剧透警告
>
> 本文是对游戏本地化文本中 5 条加密字符串的破解记录，**包含游戏内文的完整译文与专名信息**。
> 建议先自行游玩，再阅读本文。

## 零、结论摘要

`EnglishSource.uasset` 中有 5 条英文与中文**完全相同**、无法阅读的字符串
（`#0166` / `#0168` / `#0170` / `#0172` / `#0174`，共 **1037** 个字母数字字符）。
本报告确认它们是**同一套自定义维吉尼亚（Vigenère）密码**加密的**一份双向通信记录**，
并已**完整解密，零残留错误**。

| 项目 | 结果 |
|---|---|
| 密码类型 | 单表轮转（维吉尼亚），密钥逐条独立循环 |
| 字母表 | `ABCDEFGHIJKLMNOPQRSTUVWXYZ9867543210`（36 符号） |
| 密钥（5 条各不同） | `RADIUS` / `EXPLORER` / `ANOMALY` / `MIMICS` / `ARTIFACT` |
| 通信双方代号 | **ZEUS** 与 **EOS** |
| 被误认的「章节号」 | 末行 `2.0.` / `5.7.` 实为 **`P.S.`** |
| 加密范围 | 仅 `[A-Za-z0-9]`；空格、标点、换行**原样保留** |
| 验证 | 36 个符号全部反推唯一（1037 字符零冲突） |

**定界（重要）**：`ZEUS`、`EOS`、`GANYMEDE`、`TITHONUS`、`PROMETHEUS`、`GOLEM`、
`SANCTUM`、`CODENAME` 这些词在**全部 5496 条文本中均无第二处出现**（已逐词全量检索）。
因此这 5 条**不构成主线剧情的可引用证据**，只能判定为**开发期自留的彩蛋／未启用文本**。

## 二、破解过程

### 2.1 第一轮统计：排除「英文单表替换」

对 1037 个字母数字字符做统计：

| 指标 | 实测 | 参考值 |
|---|---|---|
| 重合指数 IC（全体） | **0.03107** | 36 符号均匀随机 = 0.02778；英文单表替换 ≈ 0.0660 |
| 符号熵 | **5.0627 bit** | 36 符号满熵 5.1699；英文 A–Z ≈ 4.18 |
| 单符号单词的种类 | **9 种**（`Q`×4、`S`×2、`9`/`4`/`O`/`N`/`I`/`U`/`5` 各 1） | 英文只有 2 种（`a` / `I`） |
| 词形唯一率 | 235 / 246 = **95.2%** | 等长真实英文散文约 18% |

- IC 几乎等于 36 符号均匀值、熵接近满熵 → 密文的符号分布被「抹平」，**不是单表替换**。
- 单符号单词出现 **9 种不同符号** → 单个明文字母（`a` / `I`）被映射到多个符号，
  **确定性单表替换被判死**。
- 词形几乎不重复（95.2% 唯一）→ 语言的高频词长尾结构消失，进一步支持「多表/轮转」。

按密钥长度分列计算 IC，则出现明显信号（**关键**）：

| 条目 | 最显著的密钥长度 | 该长度下的平均列 IC |
|---|---|---|
| 第 1 条 | 6（以及 12） | 0.0566 |
| 第 2 条 | 8 | 0.0647 |
| 第 3 条 | 7 | 0.0652 |
| 第 4 条 | 6（以及 12） | 0.0654 |
| 第 5 条 | 8 | 0.0692 |

结论：**每一条消息各有一个独立循环的密钥**，长度分别为 6 / 8 / 7 / 6 / 8。
（注意：若把 5 条首尾相接当作一条流去算 IC，各条的相位互相错开，周期性会被完全抹掉 ——
这是最初误判「不像维吉尼亚」的原因。）

### 2.2 第二轮：确定密钥

以游戏自身英文文本训练**四元组语言模型**（1792 条、148 509 字符、5080 种四元组），
在「游戏全部英文词 + 常用词」共 3832 个候选密钥中逐条打分，前几名立刻可读：

```
第1条  RADIUS    → … NO LHMGER BE UJING EXTERNAP NR INTEKNAL CHANNEKS …
第2条  EXPLORER  → … BUT WE HAVE OO CHOICE ANM YONK CNDLRAVES ARL OIDICULOLW …
第3条  ANOMALY   → … CODINAVES ARE GSXD UGEY QE MEANIUGFTC WE ME SENT A LITUCE GIFT …
第4条  MIMICS    → I THINK I VE BEEN CLMPVOMRTED ITHONYS WA SAKEN FVOM THE CAGE …
第5条  ARTIFACT  → WE LL TAOE CARE OF YOUR FAMILY …
```

5 个密钥全部是本作词汇，且各自长度与 2.1 的 IC 结论完全一致。到这一步已能读懂大意，
但仍有约 15% 的字符错位 —— 说明**字母表顺序还不是正确的那个**。

### 2.3 第三轮：确定字母表（本破解的关键）

把每个错误位置的「解出字符 − 正确字符」之差（Δ）列出来，发现 Δ **只由该位置的密文字符决定**：

| 密文字符 | `0` | `1` | `2` | `3` | `4` | `5` | `7` | `8` | `9` |
|---|---|---|---|---|---|---|---|---|---|
| Δ（= 数值×2 − 9） | −9 | −7 | −5 | −3 | −1 | +1 | +5 | +7 | +9 |

Δ 随数字数值**严格线性**（步长 2），这在「字母表顺序错误」时才会出现 ——
误差不是随机的，而是**字母表数字段被按数值反序摆放**造成的。由此反推：

```
字母表 = "ABCDEFGHIJKLMNOPQRSTUVWXYZ" + 数字段（按字母表位置 26→35 排列）
反推所得数字段 = 9 8 6 7 5 4 3 2 1 0
```

即 **`ALPHA = "ABCDEFGHIJKLMNOPQRSTUVWXYZ9867543210"`**。
以该字母表解密，5 条消息全部变为通顺英文、零残留错误（见第四节）。

> 说明：字母段 `A`–`Z` 保持自然顺序（0–25），只有数字段 `26`–`35` 是
> `9,8,6,7,5,4,3,2,1,0`。这个顺序**不是**从大到小的 `9,8,7,6,5,4,3,2,1,0`，
> 而是把 `6`、`7` 对调了一位。它看上去像是一段**手写的字母表字符串**
> （`A–Z` 后接倒序数字时把两位打反）。此处只记录实测结果，不推测其成因。

### 2.4 第四轮：一致性验证

用「密文 + 解出的明文 + 密钥」反推每个符号在字母表中的位置 `a(c)`：

```
a(c) = ( a(p) + a(key[i % len(key)]) ) mod 36
```

结果：**36 个符号全部反推唯一**（每个符号的出现次数 12–61 次，全部落在同一个位置上），
且没有任何符号缺席。这意味着「字母表 + 5 个密钥 + 算法」三者完全自洽 ——
若其中任何一位有误，至少会有一个符号反推出两个不同取值。

这一自检已固化进工具：`python crack_cipher.py --verify`。

## 三、解密算法（可复现）

```python
ALPHA = "ABCDEFGHIJKLMNOPQRSTUVWXYZ9867543210"   # 36 符号工作字母表
KEYS  = ["RADIUS", "EXPLORER", "ANOMALY", "MIMICS", "ARTIFACT"]

def decrypt(text, key):
    idx = {c: i for i, c in enumerate(ALPHA)}
    out = list(text)
    n = 0
    for j, ch in enumerate(text):
        if ch.isalnum():                    # 仅字母数字参与加密
            out[j] = ALPHA[(idx[ch.upper()] - idx[key[n % len(key)]]) % 36]
            n += 1
        # 空格、标点、换行原样保留
    return "".join(out)
```

仓库内的完整实现（含记录定位、顺序输出、`--verify` 自检）见
[`crack_cipher.py`](../crack_cipher.py)：

```bash
python crack_cipher.py --verify
```

## 五、内容提要

把这 5 条按时间线排开，是一段**关于内部安全、人员转移与出逃安排的双向通信**：

1. **#0166（ZEUS → EOS）**：宣布改用内部/外部双渠道之外的方式，一切走「**GOLEM**」；
   附上「**笼子（CAGES）**」的资料；期待对方「互惠」。附带一问：为什么不能用
   GOLEM 的「**SANCTUMS**」。
2. **#0168（EOS → ZEUS）**：抱怨对方的**代号很可笑**；报告「笼子」的检查
   **除第 21 项外全部通过**，并抗议被当成测试对象；称已通过 **TITHONUS** 递交一份
   关于「**影子（THE SHADOWS）**」的摘要；等待下一次转移。回问：每个 GOLEM 都有自己的 SANCTUMS。
3. **#0170（ZEUS → EOS）**：为代号辩护（「我的代号很好，它们有意义」）；
   已向「**家人（THE FAMILY）**」送出一份小礼物，正在处理下一个；
   通过 **GANYMEDE** 递送最新的研究更新；索取 **PROMETHEUS** 的细节。
4. **#0172（EOS → ZEUS）**：**自认已暴露**；**TITHONUS 被从「笼子」带走**，
   事先未获通知、未给理由；担心他会向安全部门说什么；**为家人申请人身保护**；
   附上「增援」。
5. **#0174（ZEUS → EOS）**：承诺照看其家人；追问能否离开 **PSZ**、
   在**波罗的海**是否有资产、谁能帮其**离开欧盟**；
   说明暂时不再通过 **GANYMEDE** 传递任何东西；**等待关于 TITHONUS 的消息**；
   若 5 天内无回音，将改换联络渠道。

可确认为**文本内事实**的要点：

- 双方代号 **ZEUS / EOS**；`GOLEM` 与 `SANCTUM` 是被通信双方当作既有事物的术语；
- `GANYMEDE`、`TITHONUS`、`PROMETHEUS` 是三个**具名实体**（至少 TITHONUS 是「他」，
  被关在「笼子」里、可能被带走后向安全部门供述）；
- 「**家人（THE FAMILY）**」是需要被「照看」和「申请人身保护」的对象；
- 出现了现实地缘名词 **PSZ**（= 佩乔尔斯克安全区）、**波罗的海**、**欧盟（EU）**；
- 通信内容涉及**转移、渠道、研究更新、增援**，风格是情报/安全口吻。

### 与主线的关系（定界）

## 六、仍未确定的事项

1. **字母表数字段顺序的成因** —— 实测为 `9,8,6,7,5,4,3,2,1,0`，但不清楚是开发者手写
   字母表字符串时的笔误，还是某种约定；文本不提供线索。
2. **密钥为何选这 5 个词** —— 均为本作词汇（半径/探索者/异常/拟态怪/神器），
   但是否另有取词规则（如按调色板或按任务顺序），**无法确定**。
3. **`GOLEM`／`SANCTUM`／`CAGES`／`THE SHADOWS` 指什么** —— 游戏其余文本中零命中，
   **无法确定**；只能确认通信双方把它们当作既有事物。
4. **`THE FAMILY` 是字面亲属还是组织代称** —— **无法确定**。
5. **这 5 条是否曾被设计为可获取的道具** —— 它们是 `EnglishSource` 中的孤立字符串，
   与 #0191／#0192 的对应关系**无法确定**。

## 七、复现方式

```bash
# 依赖：仅标准库
python crack_cipher.py --verify
```

工具会定位 5 条记录、按固定顺序解密、跑一次字母表一致性自检。
数据来源为仓库内的 `records_with_zh.json`（由 `prepare_records.py` 从游戏机采集的
`game_inputs/` 生成）。
